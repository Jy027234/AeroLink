# D03–D05 交易安全验收记录

日期：2026-09-08\
环境：隔离 PostgreSQL `aerolink_review`、API `3038`、前端 `5188`、Node 22、Chromium

## 已闭合规则

### D03 响应投影与重放

- 报价响应统一经过 `responsePolicy` 投影。销售提交报价及报价列表、详情、动作结果、幂等重放均不返回 `costPrice`、`costPriceDecimal`、`margin`，供应商报价原有销售可读语义保持不变。
- 订单列表、详情、动作结果及嵌套报价统一按当前 actor 投影；无 `order.view_cost` 时移除进口税、VAT、`totalLandCost`、交换核心费用及其 Decimal/日期字段，并同步约束嵌套报价成本字段。
- 报价审批快照属于审计证据，返回审批记录时仍按当前报价成本权限脱敏；无法解析的快照不直接返回原文。
- 幂等结果返回前重新读取当前单据的 owner/department 并执行授权和投影，因此降权、归属或部门变化后不会重放旧的敏感返回。
- 列表、详情、状态和嵌套对象使用同一状态映射；导出只输出允许的业务列，不把内部成本列带入 CSV。

### D04 报价审批

- 首期报价仅支持 USD；总额 `<= 5,000` 需要 MANAGER，`> 5,000 && <= 50,000` 需要 FINANCE，`> 50,000` 需要 GM。AOG 不绕过额度，高等级角色可审批较低级别。
- 默认禁止创建人审批自己的报价，错误码为 `SELF_APPROVAL_FORBIDDEN`。
- `admin` 仅代表系统管理权限，不自动获得商业审批额度；只有明确的 manager、finance、GM 角色参与对应商业审批。
- 每次审批保存策略版本、必需级别、审批业务快照及 reviewed version。快照覆盖价格、成本、利润、币种、销售条款、有效期及 RFQ 紧急程度等商业输入，不把可变并发 `quotation.version` 当作商业版本或 hash 输入。
- 旧的 `APPROVED` 记录若缺少当前策略快照，会显示 `requiresReapproval` 并进入同状态重审；重审使用 expected version/CAS 更新审批人、时间和状态历史，并追加新策略记录。并发重审只有一个请求成功，另一请求返回状态冲突。
- `send`、`accept`、`createOrderAggregate` 加载完整 RFQ（含 urgency）后重新核验当前快照，避免因为省略 RFQ 关系而错误接受或创建订单。

### D05 质量审核与出库边界

- 订单无法通过直接状态更新进入 `SHIPPED`；没有本次数量对应的质量审核，出库返回 `QUALITY_REVIEW_REQUIRED`。
- 质量主体先读取本次数量的 review snapshot，再提交件号、状态、序号/批次、数量和证据核对；订单、RFQ condition、库存 condition、序号和批次不一致时拒绝出库。
- 核心交易 E2E 保留库存数量对账：首次出库断言 `beforeQuantity = initial`、`afterQuantity = initial - 1`，第二次断言 `afterQuantity = initial - 2`，并继续校验部分/完成状态及订单最终 `shipped`。

## D03 补充：库存成本与生成文档归属边界

- `inventory.read` 与 `inventory.view_cost` 分离。`manager`、`finance`、`gm`、`admin` 可获得库存成本窄能力；`sales`、`operator`、`viewer`、`quality_manager` 仍可查询货源、数量和状态，但不返回 `unitCost`。库存列表总值在无成本权限时为 `null`，成本排序和库存 CSV 也要求 `inventory.view_cost`。
- `report.view_cost` 同样只授予 `manager`、`finance`、`gm`、`admin`。报表和定价 BI 保留运营数量/收入统计；无窄能力时库存总值、平均毛利和毛利趋势返回 `null`，不为权限不足阻断普通报表读取。
- `inventory-items` 的每一层 `details` 均经过成本投影；库存变更响应、API v1 投影和实时事件数据默认不含 `unitCost`。成本可见角色显式传入投影选项后才返回。库存消耗趋势的销售金额聚合也在无成本权限时返回 `null`，数量趋势仍可用。
- 生成文档每次读取/下载重新加载当前 quotation/order 关系并核验当前 owner/department 能力；独立文档只允许生成者或全局 `admin`。服务端以 `payloadJson` 的未知/成本字段拒绝作为确定规则，并对 HTML 内部成本标记做保守拒绝；关键词扫描不能证明任意自定义 HTML 安全，不能仅凭历史关联或创建人权限返回。详情和 PDF 对现存但无权文档统一返回 `403 AUTH_FORBIDDEN`，不存在统一 `404 RESOURCE_NOT_FOUND`，列表只返回当前可访问文档，并设置 `Cache-Control: no-store`。
