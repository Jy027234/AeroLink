## 3. 必须补入开发规格的细节

### 3.1 发货审核必须管住所有入口

[订单通用状态接口](D:/个人文件/个人开发/航材交易平台/server/src/routes/orders.ts:669)调用 [transitionOrderAggregate](D:/个人文件/个人开发/航材交易平台/server/src/modules/quotationOrder/service.ts:1109)，后者执行权限、状态转换和版本检查，但没有出库完成或质量审核条件。[状态机](D:/个人文件/个人开发/航材交易平台/server/src/lib/orderStateMachine.ts:14)允许 SO_CREATED/PO_CREATED → SHIPPED。因此，有相应订单权限的人可沿此路径登记已发货，绕开库存出库服务的条件。

另外，[订单普通编辑](D:/个人文件/个人开发/航材交易平台/server/src/routes/orders.ts:709)允许写 `inspectionRequired`、`inspectionPassed`、`certificateRequired` 等字段。以后若只增加“inspectionPassed 为 true 才能发货”，仍不足以构成可信质量关口。

**要求：**发运完成由统一履约命令检查并产生；普通字段编辑不能任意改变质量要求和审核结论。自有库存与供应商直发都要提供各自的履约证据，不能用“不走库存”作为跳过审核的例外。

### 3.2 商业版次与并发版本应分开

现有 Quotation.version 被状态迁移和库存预留更新，属于并发控制版本。不能直接把每次加一当成对客报价修订版。应保留它，另设商业 revision 或不可变报价快照，冻结价格、条款、来源和文件；审批引用具体快照。

Quotation 同时有 `expiryDate` 与默认当前时间的 `validityDeadline`；现有创建服务只显式写前者。新增有效期阻断前应明确唯一事实字段、迁移历史冲突值，并采用明确时区和截止瞬间语义，避免合法报价因错误字段被全部判过期。

### 3.3 权限策略需要跨业务对象保持一致

销售没有 `quotation.view_cost`，但具有 `supplier_quote.read`。公司应定义“不许看成本”究竟指实际进货成本、供应商报价还是毛利。统一响应不能只删除一个 `costPrice` 字段；需要按政策检查关联供货方案、文件和导出。此处是待厘清的政策边界，不将所有供应商报价可见性直接判为漏洞。

缓存的幂等响应也应进入回归范围：同一用户权限发生变化后，重试不能返回旧权限下缓存的敏感字段。此项为补充验收，尚未动态证明泄露。

### 3.4 简化通知架构需写明部署边界

单 API + 独立 Worker 时，可以让 API 仅消费 SOCKET，Worker 仅消费 EMAIL/WEBHOOK。过滤应覆盖领取、重试和管理重放等路径，避免仍由无连接实例执行 Socket 消息。

多 API 副本场景下，一条事件被一个 API 领取，不代表其他 API 上的连接会收到。应选择具有跨实例分发能力的方案，或改用每用户事件游标拉取。Socket 成功 emit 也不等于客户端可靠接收，重连应通过鉴权查询补齐状态。

### 3.5 备份恢复应从附录验收提升为真实台账准入条件

已有发布前数据库备份和运维恢复文档，不应重复从零开发。下一步应取得当前 PostgreSQL + 关联文件的一致恢复证据，并核对文档中遗留的旧数据库卷步骤。尚未取得恢复演练证据之前，不把 AeroLink 定为唯一台账。该工作与首批缺陷修复同时安排。

- [ ] **D11｜报价快照、有效期与可核实成本来源**（后端/业务，P1，F12；最小币种/有效期约束提前到正式报价开放前）\

- [ ] **D12｜数量分配与库存质量状态分离**（后端/仓储，P1，F10；依赖 D10 行关联）\

  **验收：**同一订单两次发运、两个运单的累计量正确；一个订单行可由两个批次交付；部分出库不等于整单已发完；退货不会直接增加可售余额。

- [ ] **D14｜最小采购承诺及结算摘要**（后端/采购/财务，P1，F13；依赖 D10/D11）\

### 批次 3：在真实业务上减少人工工作

- [ ] **D15｜服务端权威的受控助手任务**（后端/前端，P1；依赖 D02/D04 及所执行业务命令）\

- [ ] **D16｜邮件/附件多行草稿 → 供货比对 → 沟通草稿**（前后端/业务，依赖 D10/D11/D15）\

- [ ] **D18｜结束旧字段与旧库存兼容阶段**（后端/运维，后续收尾；依赖迁移及调用方切换验收）\

  **验收：**无未迁移调用方，对账通过，有备份和迁移记录；不得把删除旧表作为业务补强的前置大改。
