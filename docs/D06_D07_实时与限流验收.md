# D06 / D07 实时通知与限流验收记录

日期：2026-09-08

## 验收边界

当前生产拓扑是单 API + 独立 Worker：

- API 只领取 SOCKET Outbox；
- Worker 只领取 EMAIL / WEBHOOK Outbox；
- Socket 房间由服务端按当前 HTTP 会话身份计算为 user:<userId>，客户端不能自选用户房间；
- 每次投递会重新查询当前用户能力、部门和单据真实 owner；已撤销、禁用、过期的连接会在周期复核和投递前复核时断开；
- 该方案没有解决多 API 副本间的 Socket.IO 分发。扩容前需要共享 Socket.IO adapter 或用户事件游标。

Socket payload 是变化提示，只保留显式允许的实体标识和状态字段。客户名称、邮箱、报价、成本、金额和未知嵌套对象均在入队和发送边界丢弃；客户端收到提示后通过当前鉴权 HTTP Query 重新获取数据。

D07 的配额分为登录源地址桶、刷新失败/未验证源地址 abuse 桶、已验证刷新 user/session 桶和已认证业务 user/session 桶。刷新请求先验证当前用户、会话、token version 和存储的 refresh hash；验证成功只消耗 user/session 桶，不消耗共享出口 IP 桶。应用没有扩大 proxy trust。

## 可复现的本地验证

以下命令使用临时 Node 22.23.2 运行时和本地 review PostgreSQL 容器。命令中的数据库密码、JWT secret、访问令牌和 Cookie 均应由本机临时环境注入；本记录不保存任何真实 secret、token 或 cookie。

~~~powershell
$Node22 = 'C:\Users\jiaxi\AppData\Local\Temp\aerolink-node22-22.23.2\node-v22.23.2-win-x64\node.exe'
& $Node22 --version

# 后续命令均在 server 目录执行。先配置并核对隔离 URL，禁止沿用 .env 中的连接。
$env:DATABASE_URL = 'postgresql://<review-user>:<review-password>@127.0.0.1:<review-port>/aerolink_realtime_verify_<date>?schema=public'
$env:NODE_ENV = 'test'
$env:DEMO_SEED_PASSWORD = '<temporary-test-password>'
# 仅在隔离 review 容器中创建同名临时数据库，再运行项目迁移/测试种子。
docker exec <review-container> psql -U <review-user> -d postgres -c "CREATE DATABASE aerolink_realtime_verify_<date>;"
& $Node22 node_modules/prisma/build/index.js migrate deploy
if ($LASTEXITCODE -ne 0) { throw '隔离迁移失败，停止验收' }
& $Node22 --import tsx src/seed.ts
if ($LASTEXITCODE -ne 0) { throw '隔离种子失败，停止验收' }
~~~

启动 API 时使用独立端口和隔离 DATABASE_URL；示例保留了安全边界所需的开关，凭据使用占位符：

~~~powershell
$env:DATABASE_URL = 'postgresql://<review-user>:<review-password>@127.0.0.1:<review-port>/aerolink_realtime_verify_<date>?schema=public'
$env:NODE_ENV = 'production'
$env:PORT = '3047'
$env:CLIENT_URL = 'http://127.0.0.1:5189'
$env:SOCKET_OUTBOX_CONSUMER = 'true'
$env:SOCKET_AUTH_RECHECK_INTERVAL_MS = '10000'
& $Node22 --import tsx src/index.ts
~~~

另一个终端使用同一隔离数据库启动 Worker：

~~~powershell
$env:WORKER_ID = 'realtime-verify-worker'
$env:WORKER_OUTBOX_INTERVAL_MS = '1000'
& $Node22 --import tsx src/worker-entry.ts
~~~

用只包含测试 ID 和状态的 Outbox 行触发 Socket 事件。下面的 customerName / costNumber 是故意使用的非真实标记，用来确认不会穿过 Socket 边界；实际验证也应使用相同的假数据：

~~~sql
INSERT INTO "outbox_events"
  ("id", "channel", "eventType", "aggregateType", "aggregateId", "payload", "updatedAt")
VALUES
  ('realtime-socket-verify', 'SOCKET', 'rfq.updated', 'RFQ', '<seed-rfq-id>',
   '{"room":"rfqs","event":"rfq:updated","data":{"rfqId":"<seed-rfq-id>","status":"SUBMITTED","customerName":"TEST_ONLY","costNumber":"TEST_ONLY"}}',
   CURRENT_TIMESTAMP);
~~~

使用本地 Socket.IO client 登录测试种子用户并订阅连接，预期收到的事件只包含 rfqId 和 status。Worker 停止时插入的 WEBHOOK 行应保持 PENDING；Worker 恢复后才应进入 DELIVERED。不要配置真实 SMTP、真实邮件收件人或外部 Webhook。

清理只删除本次创建的临时进程和数据库：

~~~powershell
# 停止本次 3047 API 和 realtime-verify-worker 进程
docker exec <review-container> psql -U <review-user> -d postgres -c "DROP DATABASE IF EXISTS aerolink_realtime_verify_<date>;"
~~~

## 实际结果

- Node 隔离运行时为 v22.23.2，未改变系统默认 Node。
- 隔离 API（3047）消费 Socket Outbox；测试事件客户端实际收到 {"rfqId":"rfq001","status":"SUBMITTED"}，客户和成本测试字段没有发送；数据库状态为 SOCKET / DELIVERED / attempt 1。
- 停止 Worker 时测试 Webhook 保持 WEBHOOK / PENDING / attempt 0；恢复 Worker 后变为 WEBHOOK / DELIVERED / attempt 1。这证明 API/Worker 通道领取边界有效。
- 短期 access token 的 Socket 连接先输出 SHORT_CONNECTED，过期后在 10 秒复核周期输出 SHORT_DISCONNECT=io server disconnect；使用刷新接口返回的新 access token 重连输出 REFRESHED_CONNECTED。
- D07 HTTP 测试创建 31 个不同的已验证 user/session 请求，共享出口 IP 配额为 2 时全部通过；无效 refresh token 的第 3 次请求返回 429。已验证刷新没有消耗 IP 桶。
- server TypeScript 检查通过；D06/D07 定向测试 5 个文件、24 个用例通过；前端 realtime hook 测试通过；根目录 tsc -b、Node runtime 检查、功能/模块边界检查和 CI workflow contract 检查通过。

## 客户端验收状态

src/lib/useRealtimeUpdates.ts 已挂载到 App.tsx：连接、变化提示和重连会失效当前 Query；鉴权失败最多触发一次刷新尝试，失败后退出登录。对应的 RTL 单测使用 mock Socket.IO，已覆盖“鉴权失败只 refresh 一次、重连后 invalidate”。

本次服务端双进程验证使用 Node Socket.IO client，没有通过浏览器运行 React 应用，因此尚未实测浏览器端收到提示后 React Query 的真实 HTTP refetch；这项保留为浏览器验收项，不能仅以服务端 emit 成功作为完成依据。
