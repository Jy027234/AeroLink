# D11 商业成本来源验收

日期：2026-09-08\
范围：供应商报价币种与报价成本来源可追溯；不包含 D10 多行模型和下游行表工厂。

## 已实现规则

- 迁移 `20260908000300_commercial_cost_source` 新增 `SupplierQuote.currency`、`SupplierQuote.currencyReviewStatus`，以及 `Quotation.costSourceType`、`costSourceId`、`costSourceReason`、`costSourceSnapshotJson`、`costSourceCapturedAt`。供应商历史记录的币种保持 `NULL`，响应投影显示 `HISTORICAL_UNVERIFIED`，没有把未知币种静默解释为 USD。
- 新供应商报价只能写入 USD，并保存 `VERIFIED` 状态。修改币种时同样只接受 USD。件号和数量在关联 RFQ 时必须落在 RFQ 件号或明确替代件号范围内，数量不得超过 RFQ 需求量；找不到 RFQ 或不匹配会拒绝写入。
- 供应商报价创建在同一事务内解析来源身份：RFQ 只有一条已存在需求行时自动绑定该行，多行 RFQ 必须显式提供 `rfqLineId`；旧 RFQ 没有需求行时保留 `rfqLineId = null` 待核，不按件号猜测。关联询价单时，已知需求行必须唯一匹配 `InquiryItem`，并校验询价单、RFQ 与供应商归属；列表和详情返回 `rfqLineId`/`inquiryItemId` 供对账。
- 供应商报价的 RFQ、RFQ 行、询价单、询价项和件号身份不可通过更新接口迁移；已有报价或报价行引用时明确返回冲突并要求新建报价。价格和数量可以在未改变来源身份时更新并重算供应商报价总价，不会回写已审批报价的成本快照。
- 新报价必须明确 `SUPPLIER_QUOTE`、`INVENTORY_DETAIL` 或 `MANUAL` 成本来源。供应商报价来源必须属于同一 RFQ、件号匹配、数量足够、USD 已核实、未过期且单价等于报价成本。库存来源必须是 `OWN` 且状态为 `AVAILABLE`/`RESERVED`，数量检查排除当前报价自身预留，单价必须一致。人工来源必须提供明确原因，服务端不会自动补原因或接受伪造来源 ID。
- 成本来源在创建时保存不可变 JSON 快照。首次审批再次检查来源存在性、USD、件号、数量、有效期、库存自有属性和当前可用量；自身预留只计一次。审批成功后，发送、接受和创建订单只校验快照完整性，来源库存后来被消耗或数量下降不会使已审批报价失效。来源变价或快照不一致需要显式建立/修订报价。
- 没有可复核成本来源的历史报价在新审批时 fail closed。批准接口允许审核人显式补录来源，补录与当前报价的 RFQ、件号、数量、USD 和成本价一并校验，并通过报价版本 CAS 追加新的审批记录；没有补录依据不能审批。替换来源也不能走相同版本的幂等 no-op。
- 响应策略将成本来源类型、ID、原因、快照、捕获时间以及审批快照中的来源 hash 与成本字段一起按 `view_cost` 脱敏，覆盖报价列表、详情、嵌套订单、审批快照和幂等响应。具备成本查看能力的角色可读取审计来源元数据；供应商报价原有 `supplier_quote.read` 销售可读语义保留，但历史币种待核不可比价、不可标记中选。
- 当前公开销售范围仍为 USD、Sale；审批额度和禁自批策略沿用 D04，成本来源变更未放宽这些策略。D10 单行对账可直接使用已持久化的 RFQ 行和供应商报价来源 ID，跨行或来源不明的历史记录仍待核。

## 有效期历史诊断

新增 `server/src/scripts/checkQuotationValidity.ts`，在 PostgreSQL 只读事务中比较两个日期字段的精确瞬间，不依据 `validityDays` 或当前时间重算日期。当前交易和 PDF 继续以 `expiryDate` 为事实字段，新建同时写入相同的 `validityDeadline`。冲突报告只标记疑似创建时默认值，不能据此自动断言哪一个历史日期正确。

Node 22.23.2 下 3 项测试覆盖时区等价、截止瞬间到期、默认值冲突及缺失日期。在已有 E2E 的专用 `aerolink_review` 库只读检查 22 张报价：4 张已到期的 seed 历史报价存在双日期冲突，结果 `REVIEW`，其余 18 张一致。没有修改日期、延长有效期或重写历史审批。后续历史迁移需要按原始报价文件核实冲突并保留修订证据；商业 revision 和历史文件冻结仍未完成。
