# D14 采购承诺命令与接口阶段记录

日期：2026-09-09。本文记录 D14 的第二批实现；完整 D14 仍未完成，不能作为背靠背收货、供应商直发或财务结算的上线验收。

## 已实现行为

采购承诺使用独立编号和行 ID，支持同一销售行拆成多张采购承诺。服务端重读 `OrderLine -> QuotationLine -> RfqLine -> SupplierQuote`，核对当前订单、供应商、件号、实物要求、USD 核实、Decimal 成本、报价状态、有效期和数量。人工成本必须提供原因和当前操作者的可用附件；不会把 Float 或空币种补成可信成本。

已增加创建、提交、审批、拒绝、供应商确认及未收货整单取消命令。提交冻结审批快照；审批复验来源和快照，沿用 5,000/50,000 USD 分级并禁止创建人及提交人自批。管理员的技术权限不替代商业审批级别。确认保存供应商参考号和证据，不发送采购邮件，也不改变库存或客户交付量。

写入使用 Serializable 事务、版本 CAS、永久命令事件及事务 outbox。幂等缓存只保存采购 ID，每次返回前重新检查当前权限并读取当前安全投影；缓存过期后也由永久事件阻止重复命令。销售和质量响应不含采购金额、成本来源、供应商条款、确认附件或审批快照。

成本附件绑定独立 `purchase_commitment` 域。下载要求当前订单范围、采购读取及 `view_cost`，并核对业务引用中的精确版本和哈希；上传者身份、通用经理权限以及旧 `/uploads` 链接不能绕过此检查。

## 数量与并发边界

迁移 `20260909000400_order_line_coverage_guards` 将活动采购和库存分配统一校验：

```text
库存覆盖 = 分配初始量 - 已释放量
采购覆盖 = 活动采购承诺量 - 已取消量
库存覆盖 + 采购覆盖 <= 销售行成交量
```

活动采购状态为 `PENDING_APPROVAL/APPROVED/CONFIRMED/CLOSED`。已出库库存仍占历史覆盖量；消费和退货不能凭空释放成交需求。草稿和拒绝承诺不占量。D12 的订单库存预留、分配入口已接入同一检查。

数据库使用私有覆盖版本行串行化两种来源的写入，并以延迟约束验证事务最终状态；安装迁移时检查既有数据，发现超量停止迁移，不自动改写历史数量。服务层在库存写入前按订单行预锁，继续保留原库存 CAS 和数量对账。

当前仍没有采购收货来源 FK。所有现有库存分配都按非采购库存处理；不能按供应商、备注或件号猜测采购来源，也不能将采购收货再计一次需求覆盖。收货适配器必须在下一批建立明确来源后开放。

## 接口

以下入口均挂在 `/api/purchase-commitments`，写入口必须提供 `Idempotency-Key`：

| 方法与路径 | 用途 |
| --- | --- |
| `GET /?orderId=...` | 按明确销售订单读取采购承诺 |
| `GET /:id` | 当前范围内的详情及安全投影 |
| `POST /` | 从可信来源创建草稿 |
| `POST /:id/submit` | 提交并冻结审批快照 |
| `POST /:id/approve` | 独立商业审批 |
| `POST /:id/reject` | 有依据的拒绝 |
| `POST /:id/confirm` | 记录供应商确认及附件 |
| `POST /:id/cancel` | 取消尚无收货、直发的承诺 |

接口请求严格拒绝客户端件号、合计、来源快照等服务端字段。OpenAPI 和生成类型同步维护；没有定义尚未实现的收货或结算接口。
