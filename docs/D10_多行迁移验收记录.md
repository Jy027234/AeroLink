# D10 多行交易模型验收记录

日期：2026-09-08

## 变更边界

- 迁移 `server/prisma/migrations/20260908000400_transaction_lines/migration.sql` 新增 `rfq_lines`、`quotation_lines`、`order_lines`，并为 `Inquiry`、`InquiryItem`、`SupplierQuote` 增加可空来源行关系。
- RFQ、Quotation、Order 的旧单行列保留；`Order.quotationId` 的唯一约束保留。迁移本身不回填历史行，也不改变 Inquiry 的历史 RFQ 归属。
- `Inquiry.notes` 已落库；RFQ target price 的 `targetPriceCurrency` 作为需求事实原样复制，非 USD 只产生复核，不换汇。QuotationLine/OrderLine 的商业金额币种只接受 USD；供应商历史报价的未知币种保持 NULL 并报告复核。

## 回填与对账

- `server/src/scripts/backfillTransactionLines.ts` 默认只读；必须显式传 `--apply` 或设置 `TRANSACTION_LINE_APPLY=true` 才能写入。
- 写入前在 repeatable-read 快照上运行严格预检；仅允许未确认的历史询价来源作为 REVIEW，其余金额、数量、件号、关系和非 USD 商业报价异常均阻断。
- 应用事务使用 Serializable，重新读取并重新计算计划；只创建缺失且完全相同的一行，来源外键只在当前值为 NULL 时条件更新。写后对账在同一事务内执行，出现 BLOCKER 即回滚。
- SupplierQuote 的 RFQ 行路径和 InquiryItem 行路径使用同一批 effective mapping 校验，不能因同批写入顺序产生分叉来源。
- `server/src/scripts/checkTransactionLineReconciliation.ts` 为只读行对账入口；不会修复旧金额或猜测历史来源。

## 单行生命周期双写演练

- `server/src/lib/transactionLineService.ts` 是单行兼容入口的唯一行工厂：报价创建时建立稳定 `QuotationLine`，订单创建时建立 `OrderLine`；来源 RFQ 行、明确 alternate、Decimal 金额和现有行商业事实均在同一事务内校验，冲突直接拒绝。历史无行记录仍可由状态/库存流程安全跳过，直到显式回填。
- 状态服务在 RFQ、Quotation、Order 头状态变更后同步行状态；库存服务在预留、释放、部分出库和完成出库后同步 reserved/accepted/outbound、库存明细、序号和批次投影。订单当前没有 CANCELLED 状态；若未来传入取消状态，成交量同步会显式阻断，不会把已成交数量伪装成零。
- 使用独立 PostgreSQL 16 数据库 `aerolink_d10_lifecycle_202609081510`（21 条迁移，演练后已删除）走完整合成链路：报价建行、批准、预留 2、释放、再次预留 3、转订单、质量审核后部分出库 1、完成出库 2。最终对账读回 `RFQLine/QuotationLine/OrderLine` 各 1 条：`acceptedQuantity=3`、`reservedQuantity=0`、`outboundQuantity=3`、`outboundStatus=COMPLETED`，订单为 `SHIPPED`，库存明细为 `AVAILABLE` 且数量 7。
- 在同一演练库运行只读回填预检和显式 `--apply` 重复演练：两次均 `READY/PASS`、0 blockers、0 reviews，三张行表各自 `skippedExisting=1`、无新增，提交前、事务内和提交后对账均 0 blockers。
- 单元与路由回归：相关 6 个测试文件 53 tests passed；`npx tsc --noEmit` passed。状态映射统一把 RFQ `COMPLETED/WON` 映射为 `COMPLETED`、`CANCELLED/LOST` 映射为 `CANCELLED`，报价 `SENT` 映射为行表允许的 `APPROVED`。显式 SupplierQuote 成本来源会双向核对行来源 ID和头来源 ID；已审批后的供应商报价当前数量变化不会阻断生命周期同步。
