# D14 采购收货与质量来源验收

本记录对应采购承诺之后的收货增量。D14 仍在实施：供应商直发、应收应付外部凭证及岗位页面尚未完成，本批不构成背靠背闭环或生产放行。

## 行为与边界

- 到货先建立不可变的送货、实物、来源和附件事实，状态为待检；待检和拒收均不增加可用库存。
- 独立质量人员逐行验收或拒收，禁止到货人和采购经办人审核自己的收货。验收重查当前销售需求、供应商证书、寿命条件和精确附件版本。
- 验收同时创建 OWN 库存、唯一 INBOUND 流水、质量决定和采购已收货计数。拒收保留历史并允许供应商补送；不能借此登记商业退款。
- 每条验收行拥有独立库存来源键。原采购库存只能分配至原销售行；已消费量继续占用原始采购来源额度。真实退货放行后引用独立的退货来源复售，不能重新使用已消费的采购额度。
- 采购覆盖量与采购来源分配不重复相加。普通库存调整、旧整单出库及直接 SQL 均不能绕过收货来源和数量守恒。
- 收货文件使用独立访问域，不能重用采购成本文件的归属。API 和事件只返回操作所需字段；质量证书按验收记录中的精确 ID 与文件哈希衔接 D12。

## 实际数据库与 HTTP 验收环境

专用数据库为 `aerolink_procurement_test_receipts_20260909`，位于本机 PostgreSQL 16 容器的 55970 端口。它从此前纯合成采购命令库复制而来，原采购命令库和 `aerolink_review` 保留。脚本要求显式 opt-in，并拒绝连接到其他地址或数据库。

此前采购命令样本只覆盖采购流程，缺少现代 RFQ 标记、报价行成交数量及完整商业审批快照。收货校验正确拒绝了它们。本轮仅补齐 `D14-CMD-*` 合成夹具，使用真实成本快照与审批快照构造函数，加入独立 FINANCE 审批；不修改应用规则，不将夹具修复宣称为历史数据迁移。
