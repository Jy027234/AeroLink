## 1. 目标与产品定位

用户录入一个或多个件号的需求，选择供应商并发送询价，接收多家供应商邮件中的价格和交期，逐件号比较后确认供货来源。AI 参与需求整理、供应商候选建议、邮件起草、回邮提取和报价分析，业务员能查看过程并随时接手。

将现有“寻源”升级为“AI 寻源工作台”。AI 与人工共用同一份 RFQ、需求行、询价单、供应商报价和执行记录；通过任一入口操作，另一入口都能看到最新状态。此处“发布需求”指向选定供应商发送询价邮件，首期不包含公开供需市场。

本清单细化[既有待办](AeroLink_报告复核与下一步待办_2026-09-08.md)中的 D15（受控助手任务）、D16（邮件与供货比对）及 D17 的寻源工作台部分，复用已建立的 D10 多行模型和 D11 报价来源约束。以下 `SQ-*` 为该专项内部编号，不替换 D00–D18，不改变其他模块的交付结论。

## 3. 首期范围与分工

| 主体 | 职责 |
|---|---|
| AI | 从原文提出结构化需求/报价草稿，说明候选供应商依据，起草邮件，解释各供货方案差异 |
| 系统 | 校验身份与单据归属，保存来源和版本，可靠执行邮件任务，计算逐行可比价格，记录真实状态 |
| 业务员 | 修订需求与回邮提取结果，确认收件人和邮件内容，确认正式报价记录，选择每行供货方案 |

首期默认规则：

1. 沿用当前单公司内部使用及 USD 正式报价范围。非 USD 回邮可保留原文和提取草稿，但不自动折汇、改币种或纳入 USD 排名；需补充供应商 USD 报价或等待后续多币种范围。
2. 邮件正文（纯文本/HTML 表格）为首期自动提取范围。附件保留原件和来源，支持人工查看后补录；PDF、Excel、扫描件自动解析/OCR 列为后续扩展，不把文件名当作可用证据。
3. 支持供应商只报部分件号、供货数量不足、暂不报价、同一件号多个供货方案及后续修订。未回复、明确无货、识别失败和待核实分别显示。
4. 报价关联使用需求行 ID。同一需求中出现两个相同件号时仍保留两行，不凭件号文字合并；替代件仅作为显式候选，确认适用后才参与该行的比较。
5. 发送询价、确认正式报价和标记中选保留人工确认。中选代表内部供货选择，不自动发送采购承诺、不直接生成订单，也不绕过现有报价审批与采购流程。
6. AI 不可用时可手工完成同一业务流程。旧客户端运行时保持关闭，本专项只增加所需服务端操作，不开发通用 Agent 平台。

## 4. 页面与操作流程

主流程：录入/提取需求 → 选择需求行及供应商 → 确认询价邮件 → 跟踪发送与回邮 → 核对报价草稿 → 逐行比价 → 确认供货方案 → 转入现有报价/采购入口。

建议沿用现有寻源路由，在一份 RFQ 的上下文中提供：

- 需求区：件号、数量、单位、成色要求、证书要求、需求日期、已有库存匹配与缺口。
- 供应商与发送区：候选依据、联系方式、询价内容预览，以及每家供应商的排队、发送、失败和回复状态。
- 比价区：以需求行为行、供应商为列；单元格展示可供数量、单价/币种、交期、成色/证书声明、有效期和来源。一个供应商有多个方案时可展开查看。
- 邮件核对面板：原邮件/附件与提取字段对照，支持纠正关联、补录、确认或忽略。
- AI 助手与时间线：本单建议、执行进度、待确认动作、人工修订和实际结果；刷新页面或切换入口后恢复。

供应商报价页继续用于全局查询并能跳回对应需求。Agent 工作台只作为任务汇总与入口，跳转至同一业务上下文；不能维护第二份寻源事实或单独计算“已完成”。

### SQ-05｜AI 回邮提取与人工报价确认

- [x] 新增供应商回邮提取能力，复用已有模型、发布提示词和调用日志；每个候选项保留原文依据、目标需求行、供应商、数量/单位、单价/币种、交期、有效期及原文提供的成色/证书/税运费条件。

## 7. 核心验收样本

| 编号 | 场景 | 预期结果 |
|---|---|---|
| A01 | 一个件号、三家供应商分别报价 | 三份来源可追溯，按该需求行比较价格与交期 |
| A02 | 三个件号、三家供应商，回复范围各不相同 | 每行独立汇总；可分别中选；未报价行仍显示缺口 |
| A03 | 两个 RFQ 使用相同件号；一份 RFQ 内也有重复件号 | 依照业务/行 ID 关联，无法确定时待匹配，不猜归属 |
| A04 | 邮件双次同步、用户双击确认、Worker 重启 | 不重复建需求/报价/发送任务；SMTP 结果不确定时待核实 |
| A05 | 缺币种、非 USD、交期区间、缺数量、仅附件报价 | 原文保留，缺项可补录，不伪造确定值或强行排名 |
| A06 | 供应商修订报价、旧版已被下游引用 | 新旧版均可追溯，引用不变；过期方案不能继续中选 |
| A07 | 人工修订与 AI 重解析/旧任务同时发生 | 人工已确认内容不被覆盖，旧版本确认被拒绝 |
| A08 | 跨归属访问、两个操作者同时选商 | 拒绝越权，同一行中选一致，其他行不受影响 |
| A09 | 模型超时或缺配置、邮箱发送失败、无回复 | 原因与下一动作清晰；手工路径可继续，不显示虚假成功 |
| A10 | 指定真实邮箱完整发出与回复，模型参与提取 | 实际收到测试询价，回邮进入对应需求，确认报价后矩阵数据正确 |

每个样本随相关功能一次性验证并复用证据；实现、输入或相关风险变化后才重跑。真实业务试用记录人工处理耗时和修正次数，用于评估 AI 是否减负，不预设缺乏基线的节省比例。
