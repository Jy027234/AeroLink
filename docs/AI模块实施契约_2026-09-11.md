# AI 模块本轮实施契约

用户已同意完善内置智能体、提示词版本管理、模型配置与关联业务。实现以实际已有 AI 操作为基线：邮件需求提取、报价分析、客户邮件草稿、业务问答。旧客户端自动编排仍保持暂停，审批、订单和发送仍走既有业务命令。

## 协作边界

- registry agent：Prisma 两种 schema、新迁移、内置目录/版本服务、agents.ts（包括运行路由改接 root 提供的 executeAgent）、index.ts 启动初始化、相关测试。
- UI agent：AgentManagement.tsx 及新子组件、client.ts 的 agent/model 类型与 API 部分、相关前端测试。
- model agent：models.ts、aiModelService.ts（新建）、模型配置 validation 部分、相关测试。
- root：aiService.ts、aiAgentExecution.ts（新建）、routes/ai.ts、关联业务入口、契约/生成类型与集成验证、发布。

## 数据与 API

AIAgent 增加 builtinKey:String? @unique、draftRevision:Int default 0、publishedVersion:Int?；保留 config/prompts 为草稿 JSON。新增 AIAgentVersion：id、agentId、version、prompts/config JSON 字符串、createdBy?、createdAt，unique(agentId,version)，不可修改历史。两种 schema 同步，不改旧迁移。

配置使用 {modelId?: string|null, temperature?: number, maxTokens?: number}。提示词为非空 [{role:'system'|'user'|'assistant',content:string}]，至少一条 user；内置模板变量白名单，禁止未知变量。运行只读 publishedVersion 快照，草稿保存不影响已发布调用。

GET /agents：保留原字段，加 builtinKey、draftRevision、publishedVersion、workflow（内置目录的 label/description/variables/inputExample，非内置为 null）。
PATCH /agents/:id：请求必须含 expectedRevision；返回更新后 agent，冲突 409。禁止改变 builtinKey，内置 type 固定。
POST /agents/:id/publish：{expectedRevision} -> agent；原子创建新不可变版本并更新 publishedVersion，校验失败不发布。
GET /agents/:id/versions：版本数组（version、prompts、config、createdBy、createdAt）。
POST /agents/:id/restore：{version,expectedRevision} -> agent；仅复制历史为新草稿，须再显式发布。
POST /agents/:id/test：{input: object} -> {output:string,model:string,latency:number,promptVersion:number,agentId:string}；只执行已发布提示词，不写业务单或发送邮件。需 agent.manage + agent.run。
既有 /agents/:id/run 同样执行已发布快照，不接受 input.systemPrompt 绕过配置；按内置任务限定 task，保留 run 能力校验。

root 提供 executeAgent(agentId:string,input:Record<string,unknown>,context?:{actorId?:string;action?:string}) 返回上述测试结果。路由需把 req.user.id 传入。registry 导出 ensureBuiltinAgents()、BUILTIN_AGENTS（key/name/type/description/prompts/config/variables/inputExample）、getBuiltinAgent(key)；key 固定 rfq_extraction、quote_analysis、customer_email、business_chat；id 为 builtin-<key>。版本服务独立可测试。根负责运行时读取数据库及模板替换。

初始化幂等且只补缺少的内置记录与 v1，不覆盖用户修改，不调用演示 seed。正式启动前初始化；测试导入路由不隐式写库。

## 模型

首期明确支持 OpenAI 协议兼容提供商 openai/deepseek/ollama/custom；不展示尚未实现的 Anthropic/Azure 适配为可用。自定义 modelId 可填写，baseUrl 须校验，非本地服务使用 HTTPS。密钥使用现有 AES-GCM 加密工具存储并带 enc:v1: 前缀；兼容读取旧明文，所有模型响应只返回 hasApiKey，不回传密钥。默认模型设置用事务。

model agent 导出 resolveAIModel(modelId?:string) -> {id,modelId,provider,apiKey?,baseUrl?,config:Record<string,unknown>}（仅服务内部使用），必须拒绝禁用/无模型/缺少所需密钥，支持既有环境密钥回退但无 sk-demo。导出 serializeAIModel() 供路由；模型连接测试仍调用 generateCompletion，只返回可控结果和脱敏错误。

## 验收

空库显示真实内置目录；草稿/发布/恢复/并发冲突；发布提示词影响模型实际收到的请求，草稿不影响；停用、缺少模型和无权限明确拒绝；敏感密钥不回传；相关业务调用经过相同执行器并记录版本、实际模型及调用身份。用隔离数据库和本地协议模拟器验证，实际外部模型凭据由用户页面配置，不伪造模型成功。
