# AI 智能体、提示词与业务接入

本轮针对“AI 智能体页面为空、业务提示词无法管理”的问题，实现真实内置目录、模型配置、提示词草稿与发布版本，并接入四个业务入口。现有审批、建单、供应商选择和邮件发送仍由用户通过原有业务流程确认。

## 入口

系统设置 → AI 智能体 → 智能体配置 → 内置智能体目录。点击“编辑配置”可管理 role/content 提示词、模板变量、模型、温度和输出长度；同一页面提供版本历史、恢复草稿和试运行。

系统设置 → AI 智能体 → 模型管理。新增模型，填写服务商、模型 ID、必要的 API Key 与服务地址，设为默认模型后点击“测试连接”。密钥加密保存且不回显，修改模型时密钥留空保持原值。

系统设置 → AI 智能体 → 调用记录。按智能体查看实际业务调用的时间、动作、用户、提示词版本、模型、状态与耗时；不展示原始业务输入或输出。

| 内置智能体 | 实际业务入口 | 输入与结果 |
| --- | --- | --- |
| RFQ 需求提取 | 需求归集 → 邮件详情 → AI 提取需求建议 | 服务端读取邮件；返回件号、数量、紧急程度等。用户选择建议填入待确认卡片并审核后建单。多项需求全部显示，当前卡片一次创建一项，其余项需补入 RFQ 明细。 |
| 报价分析 | 供应商报价 → 筛选一个 RFQ → AI 报价分析 | 服务端按用户权限读取 RFQ 与相关供应商报价，生成价格、交期及风险建议；不自动选中供应商或定价。 |
| 客户邮件草稿 | 报价管理 → 发送报价邮件 → 生成 AI 邮件草稿 | 使用面向客户的报价及全部报价明细，排除供应商成本、利润与内部备注。先预览，点击采用才替换邮件正文，原发送与审批校验继续有效。 |
| 业务问答 | AGENT 工作台 → AI 业务问答 | 根据用户提供的信息答复；不自动读取未提供的业务记录，不执行审批、订单或邮件发送。 |

需求归集原有正则提取保留为“规则提取”，不会冒充 AI 成功。模型未配置、停用、认证失败或 RFQ 输出不符合格式时会明确报错，保留用户编辑内容。

## 草稿与发布

1. 修改提示词或模型参数后，先保存草稿。
2. 检查后点击发布，生成不可修改的版本快照；业务调用从此使用该版本。
3. 试运行始终执行已发布版本，显示实际响应模型、提示词版本和耗时。
4. 恢复旧版本只修改草稿；需要再次发布才生效。并发修改使用修订号校验，过期请求返回冲突，避免覆盖他人的更改。

智能体启用/停用立即生效；提示词和模型参数需要发布。内置智能体不可删除，以保留业务绑定与版本历史。启动仅补齐缺少的内置目录，不运行演示 seed 或改写已有业务记录。

## 模型兼容范围

支持 OpenAI、DeepSeek、Ollama 与 OpenAI 协议兼容服务（custom）。模型 ID 手动填写，需使用对应服务实际提供的 ID；其他 API 协议尚未适配。

- OpenAI：地址留空使用官方 API；使用 completion token 参数。不接受 temperature 的模型可启用“不向提供商发送 temperature”。
- DeepSeek：地址留空使用 `https://api.deepseek.com`。本次用户选择 DeepSeek，默认业务模型采用其 [官方 API 文档](https://api-docs.deepseek.com/) 当前列出的 `deepseek-flash`；模型 ID 仍可在页面修改。这批提取、分析和草稿功能显式使用非思考模式，避免思考过程耗尽正文的输出额度；参数依据 [思考模式说明](https://api-docs.deepseek.com/guides/thinking_mode/)。
- Ollama：填写 OpenAI 兼容地址，例如 `http://localhost:11434/v1`。localhost 指 API 服务器/容器，不能代表访问网页的用户电脑。仅本地 Ollama 允许无密钥。
- custom：显式填写服务地址和密钥。远程服务使用 HTTPS，URL 不允许包含用户名、密码、query 或 fragment。

智能体未单独指定模型时使用启用中的默认模型。默认模型缺失或停用会拒绝执行，不自动改用其他模型。配置或启用并不代表连接测试通过，页面区分这些状态。

服务端每次执行记录调用人、提示词版本、实际模型、耗时、状态及输入/输出摘要哈希；不把完整业务邮件、报价或模型密钥写入调用日志。现有加密密钥轮换脚本已覆盖新增的加密模型密钥。

## 验证与边界

本轮新增单元测试覆盖发布快照、草稿隔离、权限、数据投影、输入变量、RFQ 输出校验、密钥加密与脱敏、模型错误，以及用户明确采用草稿与丢弃跨记录迟到响应。

`server/src/scripts/checkAiModuleIntegration.ts` 只允许显式确认的 `ai_module_test` PostgreSQL 隔离数据库，以本地 HTTP 模型协议服务验证真实路由、数据库版本发布、恢复、并发与请求内容；该验证已接入 CI。协议模拟器不是外部模型效果验收。

用户已选择 DeepSeek，尚未提供 API Key。测试服务器已预设“DeepSeek 业务助手”为默认模型，模型 ID 为 `deepseek-flash`、地址为 `https://api.deepseek.com`；页面明确显示缺少密钥，外部模型尚未验证连通。管理员在“模型管理”中编辑此模型、填写自己的 API Key 后，先测试连接、试运行，再用真实业务样本评估输出质量；密钥无需发到对话里。
